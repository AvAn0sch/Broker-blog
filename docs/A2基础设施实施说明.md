# A2 基础设施实施说明

日期：2026-10-15。范围：首批数据结构、版本化迁移、事务与错误协议、提交防重、事务事件、持久任务、测试隔离。账号登录和面向用户的业务流程从 A3 开始实现，本文不表示全部 P0 用例已经通过。

## 1. 数据库与迁移

首批 22 张表覆盖 users、sessions、captcha_challenges、rate_limit_buckets、articles、article_drafts、article_publications、review_requests、tags、media、三套标签关联与三套媒体关联、idempotency_keys、domain_events、jobs、job_receipts、notifications、audit_logs。点赞、收藏、关注、评论、举报与精选在对应功能阶段继续增加版本化迁移。

`src/infrastructure/db/schema.ts` 是 Drizzle 结构来源。`0000_a2_foundation.sql` 创建表、约束与索引；`0001_a2_guards.sql` 创建数据库不变量：审计禁止修改/删除/清空，事件和任务回执仅追加，文章归属和首次发布时间稳定，已删除文章不能恢复，工作草稿更新必须推进版本，送审内容及引用固定，标签 slug 稳定。后续迁移不修改以上历史：`0002_a3_identity.sql` 增加验证码并发约束，`0003_b1_media_readiness.sql` 由 B1 增加媒体校验和、上传租约与失败原因列及状态机约束，见 [B1 实施说明](B1草稿与受控媒体实施说明.md)。

送审内容和标签/媒体引用必须在同一事务内创建。引用触发器核对送审记录的创建事务，提交后不能再增加、修改或删除该快照引用；复核记录只能从 pending 结案并递增版本，通过/驳回要求处理人、原因和时间。这些规则不代替后续服务层的权限和业务前置条件检查。

开发库默认使用 public。测试每轮使用 `bbtest_<32位运行标识>`，连接 search_path 仅包含本命名空间，不回退 public。生成脚本把新迁移中 Drizzle 默认的 `REFERENCES "public".` 转成无 schema 前缀的引用；转换后的 SQL 随代码提交并审查，执行时不动态替换 SQL。这样开发、测试和 Linux 执行同一迁移文件。包含硬编码 public 引用的迁移会被执行器拒绝。SQL 文件固定 LF 换行，保持跨平台 hash 一致。

迁移使用专用数据库连接和 advisory lock 串行执行，迁移日志也保存在本命名空间。执行前逐条比对已应用记录的 hash 与时间序列，修改已应用的历史文件会被拒绝。后续变更创建新迁移，不覆盖旧迁移，不使用 push 静默同步。

```powershell
pnpm db:generate --name change_name
pnpm db:migrate
pnpm db:seed
```

`db:seed` 仅在 development/test 初始化 8 个预置标签，重复执行保留已有资料；不创建可绕过密码验证的账号。A3 接入密码哈希与受限管理员初始化后再提供账号数据。

## 2. 事务、授权与重复提交

`withTransaction` 统一 BEGIN/COMMIT/ROLLBACK，提供同一连接的 SQL 和 Drizzle 对象；锁等待最长 5 秒，语句最长 15 秒。仅死锁/序列化失败最多重试 2 次。回调不得执行文件写入、发送消息等数据库外副作用；响应丢失交由提交标识重试处理。

`withIdempotency` 在调用者事务中按“用户、操作、UUID 提交标识”唯一。请求采用稳定 JSON 序列化和 HMAC-SHA256 摘要，同键不同内容返回 409。首次成功仅保存资源 ID 和可选版本；失败整个事务回滚，不残留已完成标识。重放成功结果仍执行调用者提供的授权检查，不能在账号封禁后绕过权限。

账号状态检查使用 `FOR NO KEY UPDATE`：它与并发幂等记录插入所持有的外键 KEY SHARE 锁兼容，同时与账号封禁的更新互斥，避免“先幂等、后账号”锁顺序因隐含外键锁发生死锁。A3 仍须从真实会话解析用户，不能接受浏览器任意指定 actorId。资源可读性检查由对应业务用例补充。

`apiResponse` 统一返回 `{data,requestId}` 或 `{error:{code,message,fieldErrors?},requestId}`，服务器生成请求 ID，响应禁止缓存。数据库唯一性、关联、字段和暂时冲突映射为确定错误，未知异常不返回 SQL、堆栈或私人输入。基础接口 `/api/v1/health` 已使用此协议；运维健康检查继续保留原有简洁格式。

## 3. 事务事件与持久任务

`enqueueEvent` 必须接收当前事务对象，事件与任务随业务一起提交。事件载荷当前只接受 UUID 引用字段，禁止将完整正文或凭证作为任务载荷。每事件/处理器只能有一条任务。

任务状态：pending → running → completed；失败进入 retry 或 failed。领取使用 `FOR UPDATE SKIP LOCKED`，租约 60 秒，每次领取更换随机 token、增加尝试次数。完成、失败、续租均比较当前 token 及租约，旧进程不能覆盖新领取者。默认最多执行 6 次，重试间隔依次为 5 秒、30 秒、2 分钟、10 分钟、30 分钟；最后一次执行中断也会留下可查询的 failed 状态。

数据库副作用与 job_receipts 同事务提交，然后单独确认任务完成。若结果已写而确认前中断，下一进程看到回执后跳过副作用。notifications 另有“事件、接收者”唯一约束。处理器仍须把全部数据库写入放在收到的事务里；本机制不承诺数据库外副作用恰好一次。

当前 worker 串行每次领取 1 条，事务语句超时小于租约，避免一次领取多条后尾部任务尚未执行租约已过期。批量领取与显式续租能力可供后续处理器使用。当前注册内部 `system.probe` 处理器，业务通知接收规则在 C4/D 实现。没有公开的任务注入或故障控制接口。

```powershell
pnpm jobs:probe
pnpm worker:once
pnpm jobs:status
pnpm jobs:retry <失败任务的UUID>
pnpm worker
```

probe 生成只允许 development/test；status/retry 是使用本地数据库凭证的运维脚本，不是管理员网页。状态输出不包含任务载荷或租约 token。

## 4. 测试隔离与报告

`pnpm test:foundation` 只执行基础持久化用例；`pnpm verify:foundation` 执行类型、规则、接口、基础持久化和两个视口的完整当前回归。旧的 `test:api`、`test:e2e`、`verify:environment` 保持可用。

每轮创建随机运行标识、独立 schema、迁移日志、标记表、媒体目录、故障控制实例和新浏览器上下文。worker 子进程继承本轮 schema。受控时钟和一次性故障仅能在 APP_ENV=test、TEST_CONTROLS=true、运行 ID 与 schema 匹配时创建；没有通过普通请求头或接口触发的入口。

完成或失败后，清理核对测试环境、数据库名、连接身份摘要、schema 前缀、数据库与文件标记、规范化绝对目录及真实路径，再删除本轮 schema 和媒体；报告与 manifest 保留。清理可重复执行，失败使整轮失败，不能宣称环境干净。异常资源可通过 `pnpm test:cleanup <运行标识>` 重新核对后清理。

报告位于 `.local/test-runs/<运行标识>/reports/`，包含 Playwright JSON/HTML、诊断产物、summary.json 和 summary.md。汇总记录 commit、未提交业务变更状态、运行 ID、配置/数据集/浏览器版本、用例统计和清理结果。原有未跟踪的 prototype 参考目录不计入业务 dirty；新业务文件计入。报告不包含数据库密码、会话凭证或私人正文。

Linux Compose 先完成 migrate 服务，再启动 Web 和 worker；test 服务运行同样的验证入口并把运行目录保存在宿主机。容器内基础测试使用独立 schema；当前无业务写入的页面冒烟访问已迁移的服务 schema。A3 起引入真实业务浏览器流程时，应继续让整套应用/worker 绑定对应运行环境；完整两轮独立初始化验收仍以 E 阶段门槛为准。
