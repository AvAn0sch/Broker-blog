# B1 草稿、公开内容、复核快照与受控媒体实施说明

日期：2026-10-15。范围：三份内容模型独立性的复核与引用校验、受控媒体上传与读取、媒体引用表、失败恢复与清理。编辑器界面、本地恢复与保存调度从 B2 开始，本文不表示 MEDIA-02 的治理范围已全量验收。

## 1. 三份内容模型

A2 已建立三份彼此独立的内容模型，B1 复核其守卫并在引用层补充校验：

| 模型 | 表 | 关键规则 |
| --- | --- | --- |
| 文章身份与状态 | `articles` | 归属与首次发布时刻稳定；状态变更必须递增 `state_version`；已删除不可恢复 |
| 工作草稿 | `article_drafts` | 更新必须恰好推进一次版本；正文长度受限；不对外读取 |
| 公开版本 | `article_publications` | 绑定 `source_draft_version`；标题与正文非空；只有确认版本进入公开读取 |
| 复核快照 | `review_requests` | 只为固定草稿版本创建；结案前内容不可改；标签与媒体引用必须在提交事务内固定 |

标签与媒体各有三套关联（`draft_*`、`publication_*`、`review_*`），互不影响。B1 新增的引用校验 `validateReferences` 在发布、修订与送审事务内执行：媒体必须存在、`status='ready'`，且属于当前账号——不允许通过引用他人私有图片使其公开。未完成上传的图片无法取得可发布引用。

## 2. 媒体存储与上传

### 2.1 受控目录与存储键

图片保存在 `MEDIA_ROOT`，环境校验已强制该目录位于 `public` 之外，不由静态服务器映射、不开放目录枚举。存储键全部由服务端生成：`<ownerId>/<mediaId>.<扩展名>`，客户端只提交字节，从不提交路径或文件名。键格式由正则约束，另加“解析后必须落在根目录内”的包含性检查：解析目标路径，并对最深的已存在祖先做 `realpath` 比对，符号链接与 Windows 目录联接（junction）越界都会被拒绝。

### 2.2 真实类型与边界

只接受 JPEG、PNG、WebP。服务端不信任声明的 `Content-Type`，而是按字节做结构校验：

- PNG：签名、IHDR 长度与类型、非零宽高、IDAT 存在、IEND 位于末尾且长度为 0；
- JPEG：SOI/EOI 标记、按段长度遍历、SOF 段解析宽高；
- WebP：RIFF 长度与文件长度一致、`WEBP` 标识、首个块为 VP8X/VP8L/VP8 且块长度在界内，按各自头部解析宽高。

这里做的是结构校验（签名、尺寸、容器结束与分块边界），不是完整像素解码；重命名、截断与伪造文件会被拒绝。单张上限固定为 **5 MiB（5242880 字节）**，边界用例覆盖等于上限与超出 1 字节两种输入。

### 2.3 上传流程

1. 校验 Origin、会话与 CSRF，确认账号为正常状态（复用 `authenticatedTransaction`）；未登录返回 401，Origin 或 CSRF 不符返回 403。
2. 按“账号 + 全局”两个固定窗口限流（默认每账号每小时 30 次、全局每分钟 300 次），超出返回 429。
3. 校验体积与真实类型；随后在事务内登记 `staging` 记录：服务端生成存储键，写入上传租约（默认 60 秒），此时不写校验和。
4. 事务之外写文件：先写 `<键>.partial` 并 `fsync`，再原子重命名到最终键——事务回调不执行文件写入。
5. 在事务内把记录置为 `ready`、写入 SHA-256 校验和并清除租约；同一事务写入幂等回执。

文件的可靠写入与数据库登记不是同一个事务，因此幂等回执只在文件完整之后记录：**失败的尝试不会被重放成成功**，同一提交标识可以在失败后重试。相同键与相同内容的重放返回同一个 `ready` 媒体（`replayed: true`）；相同键不同内容返回 409。并发提交同一键时只有一个媒体保持 `ready`，落败方的记录标记为 `duplicate_upload` 并删除自己写入的文件。

状态字段由数据库 CHECK 约束强制：`staging` 必须带租约且无校验和，`ready` 必须无租约且有校验和，`failed` 必须无租约、无校验和且有失败原因。

## 3. 读取授权

`GET /api/v1/media/:id` 每次请求按当前状态判定，不缓存（响应带 `no-store` 与 `X-Content-Type-Options: nosniff`）：

| 主体 | 允许条件 |
| --- | --- |
| 所有者 | 始终可读自己的 `ready` 媒体 |
| 游客与任意成员 | 媒体被当前 `published` 文章的公开版本引用 |
| 游客与任意成员 | 媒体被已保存的账号头像引用 |
| 正常管理员 | 媒体被固定送审快照引用，或被 `taken_down` 文章的公开版本引用 |
| 其他情况 | 拒绝 |

草稿引用不授予管理员任何额外权限；封禁管理员立即失去治理读取权。不存在与无权访问统一返回 404，避免通过状态码枚举他人私有媒体。下架或删除会使该公开引用立即失效；同一媒体若仍被其他有效公开内容引用则保持可读。

## 4. 失败恢复与清理

| 场景 | 结果 |
| --- | --- |
| 写文件失败 | 记录置 `failed`（原因 `storage_write_failed`），删除半成品，请求返回 503，不产生可发布引用 |
| 文件已写但数据库未确认 | 记录停留在 `staging`，文件已在最终键；租约过期后 `recover` 校验文件并置 `ready`，校验和不匹配或文件缺失则置 `failed` 并清理 |
| 结构校验不通过 | 不接受该上传，不创建记录 |
| 响应丢失 | 使用相同提交标识重试即返回原 `ready` 媒体 |

运维入口（使用本地数据库凭证，输出不含内容与凭证）：

```powershell
pnpm media:recover
pnpm media:cleanup
pnpm media:verify <媒体UUID>
```

`cleanup` 只处理超过宽限期（默认 24 小时）且没有记录、或记录为 `failed`、或 `ready` 但无任何引用（草稿、公开、复核、头像四类引用都算）的对象；删除前锁定媒体行并二次检查引用，处于活动上传租约中的 `staging` 记录一律跳过。`verify` 在独立进程中按存储键读取文件并输出数据库与文件的校验和、类型，用于跨进程持久化佐证。

## 6. 测试与验证

- `tests/rules/media.test.ts`：尺寸边界、真实类型与结构拒绝、存储键格式与路径形态拒绝（5 项）。
- `tests/foundation/media.spec.ts`：真实文件落盘与所有者读取、伪造/超限不产生记录、写失败与可重试、文件已写而数据库未确认的恢复、未完成媒体不可引用、同键重放与并发唯一、路径越界与目录联接拒绝、跨进程读取、上传限流、清理只作用于无引用对象（10 项）。
- `tests/api/media.spec.ts`：真实上传与回读、浏览器编码的 JPEG/WebP 保持真实类型、伪造与超限拒绝、Origin/CSRF/登录要求、私有媒体对游客与他人的隔离、公开引用与下架撤权、头像与送审引用及草稿引用不授权、同键重放（8 项）。
- 运行命令：`pnpm verify:auth` 执行当前完整回归；报告配置版本 `b1-v1`，数据集版本 `identity-media-v1`。

开发态与并发约束（测试侧口径，不放宽产品参数）：

- 密码哈希在每个 Web 进程最多并发 2 次，超出立即返回可重试 503；该阈值在开发、测试与生产一致。B1 新增约 10 次真实注册，浏览器用例在收到 503 或刷新验证码窗口内的 `CAPTCHA_*` 400 时按提示重试，并在重试前重新加载表单。
- 开发态按需编译新路由会向已打开页面发出整页刷新信号，可能打断提交后的客户端跳转。浏览器用例因此核对真实结果——响应 200 之后确认会话已建立、目标页可达——而不是只依赖一次客户端跳转；注册与登录仍走真实表单与真实接口。
- 注册与登录表单在 `loading`/`pending`/无挑战时会静默忽略提交，因此用例先确认提交按钮可用再点击；注册与登录各含真实哈希的两条认证用例申请了更长预算。
- 注册响应超时或丢失后重试会得到 409（邮箱已存在）；用例按产品文案的指引改用登录确认并建立会话，而不是把重复注册当失败——这也是产品对“响应丢失”的一贯口径。
- 清理扫描会跳过媒体根目录中非媒体键形态的文件（例如测试验证码答案与 worker 心跳），只处理媒体对象。
- 清理用例使用独立的作用域存储根：`cleanup` 会扫描整个存储根并用受控时钟判断宽限期，若与同轮其他用例共享根目录，会删除它们刚上传、尚未建立引用的真实图片。
- 接口用例在文件内共享测试账号：验证码与注册的全局限流按分钟统计，逐用例注册会在执行更快的容器轮次中触碰产品限流（本轮实测）。限流参数不为测试放宽。
- 请求 `Origin` 取自 Playwright 的 `baseURL`，与浏览器用例的应用入口保持单一来源；容器内测试进程的 `APP_ORIGIN` 可能与应用实际入口不同。
