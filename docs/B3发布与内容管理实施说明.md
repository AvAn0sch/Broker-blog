# B3 发布、修订、逻辑删除与内容管理

日期：2026-10-15。范围对应开发规划 B3：ARTICLE-01、EDIT-03 发布版本绑定、TXN-01 发布事务、OUTPUT-01 服务端正文，以及 MEDIA-01/02 的发布与删除部分。首页分发、标签详情、作者主页和资料属于 B4；搜索、互动、通知及治理复核按后续阶段实施。

## 1. 使用流程

1. 在 `/editor/new` 或 `/editor/:id` 编辑标题和正文，点击“发布文章”或“更新文章”。
2. 发布配置读取数据库中的真实标签，填写可编辑摘要并选择 1–3 个有效标签。空摘要自动从 Markdown 的纯文字生成，最多 200 个 Unicode 码点。
3. 点击“保存并确认版本”。编辑器等待正在进行的保存及期间产生的后续保存完成，再读取服务器草稿，确认本窗口的修订号及草稿版本均未变化。
4. 弹窗明确展示已保存的草稿版本，点击“确认发布”提交该版本和文章状态版本。保存失败、版本冲突或标签失效均保留当前输入并显示原因；不会自动改用其他窗口的版本。
5. 发布成功进入 `/articles/:id`。已发布文章的草稿继续独立保存，只有再次确认更新才替换公开内容。首次发布时间和 URL 保持不变。
6. `/me/articles` 按全部、草稿、已发布、已下架筛选，展示未发布修改、下架原因和现有复核状态。删除弹窗二次确认；失败可重试，同一次删除重试沿用提交标识。

封禁账号只能查看本人的管理列表和只读草稿，不能发布、保存或删除。已下架文章可编辑工作草稿，但没有直接发布入口，须等待后续复核流程；删除仍可使用。删除后列表不再展示，编辑页与游客详情不可读取，没有界面恢复入口。

## 2. 接口与版本

| 接口 | 请求与结果 |
| --- | --- |
| `POST /api/v1/articles` | 草稿字段可带 `tagIds`；创建在同一事务登记草稿标签和图片引用 |
| `GET/PATCH /api/v1/articles/:id/draft` | 增加 `status`、`stateVersion`、`tagIds`；PATCH 带 `baseDraftVersion`；省略标签时保留原关联，显式空数组清空 |
| `POST /api/v1/articles/:id/publish` | `{stateVersion,draftVersion}`，绑定已保存版本；返回 `{articleId,stateVersion,replayed}` |
| `DELETE /api/v1/articles/:id` | `{stateVersion}`，逻辑删除；返回同样的最小写入回执 |
| `GET /api/v1/articles/:id` | 仅当前 published 的公开 DTO；即使作者访问也不能获得未发布草稿 |
| `GET /api/v1/me/articles` | 本人列表；`status=all/draft/published/taken_down`、`limit=1..50`、`cursor`；默认每页 20 条 |
| `GET /api/v1/tags` | 标签 ID、slug、名称、有效状态；停用标签可辨识和取消，不能用于新发布或更新 |
| `GET /sitemap.xml` | 按当前状态生成，仅收录已发布详情；无缓存 |

所有写入复用会话、精确 Origin 和 CSRF 校验，并在业务事务内重新检查账号和文章归属。其他用户（含管理员）不能代作者发布或删除；统一返回 404。成功重放仍校验当前身份和权限，只返回资源 ID 与原状态版本，不返回可能已失效的内容。相同提交标识不同请求返回 409。

草稿保存只增加草稿版本；发布/更新/删除增加文章状态版本。服务端锁定文章后比较状态版本，再锁定草稿核对确认版本；版本不符时整个操作失败，不自动重试为新版本。

## 3. 事务、内容隔离与媒体

采用现有表，无新增迁移，也不修改历史迁移。写入顺序为幂等记录 → 当前用户 → 文章 → 草稿/待处理复核 → 排序后的标签 → 排序后的媒体 → 关联与事件。标签共享行锁与停用更新互斥，媒体引用校验与清理锁相同媒体行。

发布事务复制指定版本到 `article_publications`，整体替换 `publication_tags` 与 `publication_media`，更新文章状态、首次/更新时间并写入 `article.published` 事件。删除事务递增状态版本、将待处理复核终止并写入 `article.deleted` 事件。任一步失败，公开内容、关联、状态、事件和幂等回执共同回滚。发布本身不发送通知，因此这些内容事件没有虚设的通知任务。

`article_drafts` / `draft_tags` / `draft_media` 始终属于工作草稿；公开读取只查询 publication 表，绝不拼接工作草稿。公开 DTO 明确限定为文章 ID、标题、正文、摘要、公开作者 ID/昵称、标签、首次发布时间和更新时间，不序列化邮箱、密码、磁盘键、状态版本或私有修订。

发布使用与渲染相同的 CommonMark/GFM 解析器识别实际图片，包括引用式图片；代码示例不会被当作图片。实际图片只允许严格的 `/api/v1/media/<UUID>` 地址，拒绝外链、data/blob、路径参数和无效 ID，并在事务内重新核对 ready 和归属。临时故障适配器只在内部测试代码注入，不提供 HTTP 控制入口。

删除保留内部记录和原有引用用于追踪；媒体公开授权仍须关联状态为 published 的文章，因此删除后新读取立即撤权。所有者仍可访问自己上传的文件，同一图片若仍被另一篇有效公开文章引用则仍公开。完整治理权限与保留周期不在 B3 声称验收。

## 4. 正文输出与页面

文章标题、摘要、作者、时间、标签、Markdown 正文及目录由服务端输出；禁用 JavaScript 仍能读取完整正文。预览和正文共用 `react-markdown`、GFM 和高亮规则，显式跳过原始 HTML，过滤链接协议，仅渲染受控图片。页面提供稳定章节锚点、桌面目录/移动折叠目录、代码复制和固定链接；长代码块独立滚动。

动态 metadata 使用公开标题、摘要和规范 URL；页面通过 Next.js 当前安装版本的 `connection()` 在请求时读取，React `cache` 仅在同一渲染请求内合并正文和 metadata 的读取。没有共享内容缓存；API、媒体和站点地图返回 no-store。非公开内容在详情、DTO、metadata 与站点地图均不返回正文。

本人分页以不可变创建时间与 ID 倒序作为游标，保留 PostgreSQL 的微秒时间文本，避免转为 JavaScript Date 后丢失精度、跳过同毫秒记录。筛选切换从第一页开始。

直接依赖固定增加 `unified@11.0.5`、`remark-parse@11.0.0`，均为已有渲染链所用版本；没有新增编辑器或渲染框架。标题/正文/摘要上限按 Unicode 码点计数，与数据库一致；本地副本新增可选标签字段，兼容旧副本。
