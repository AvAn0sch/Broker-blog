## 2. 编辑与预览

`/editor/new` 与 `/editor/:id` 都在全局骨架内渲染 `src/features/editor/editor.tsx`：标题输入、Markdown 源码（CodeMirror 6）、阅读预览、保存状态、本地备份状态与操作区。桌面并排显示编辑与预览，窄视口通过“编辑/预览”切换，只显示一个面板。

预览与公开正文共用 `markdown.tsx`：GFM、代码高亮、**禁用原始 HTML**（不引入 `rehype-raw`），链接只允许 `http:`、`https:`、`mailto:` 与站内相对地址（`javascript:`、`data:`、`vbscript:`、`file:` 一律丢弃）。图片统一使用受控地址 `/api/v1/media/:id`，预览直接读取该受控入口。

## 3. 草稿接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/articles` | 创建私有草稿；带提交标识时幂等，重试返回同一文章，不生成重复草稿 |
| `GET /api/v1/articles/:id/draft` | 仅作者可读（其他账号一律 404）；封禁作者仍可只读 |
| `PATCH /api/v1/articles/:id/draft` | 携带 `baseDraftVersion`；`WHERE version = baseDraftVersion` 条件更新，旧窗口不能覆盖新文本（409 `DRAFT_VERSION_CONFLICT`） |

写接口复用 `authenticatedTransaction`（精确 Origin + 会话 CSRF + 实时账号状态），保存失败写入统一错误协议。保存时解析正文中的受控媒体引用并同步 `draft_media`：引用他人私有媒体返回 403 `MEDIA_FORBIDDEN`，引用未完成上传的媒体返回 409 `MEDIA_NOT_READY`；草稿允许处于未完成编辑状态，但引用集合每次保存整体替换。

## 4. 保存调度、本地恢复与冲突

节奏固定在 `contentPolicy.autosave`：输入后最长 1 秒写入本地副本，停止输入 3 秒保存到服务器，持续输入最长每 30 秒保存一次；手动保存随时可用。

本地副本写在 IndexedDB（`broker-blog-editor` / `copies`），键为 `(userId, draftId, editorSessionId)`：

- 窗口标识保存在 sessionStorage，刷新沿用；新标签页没有该值，因此天然获得新标识；复制标签页会带走同一标识，启动时通过 BroadcastChannel 握手探测占用并分配新标识，**绝不覆盖另一窗口的副本**。
- 每个窗口只写自己的键；恢复对话框列出该草稿的全部未同步副本（标注本窗口/另一窗口与基础版本），可按需恢复或放弃。
- 临时草稿创建成功后，本窗口副本键迁移到真实文章键，保留文本与基础版本。
- 本地存储不可用时明确提示「本地备份失败」并引导导出，绝不宣称已备份；存在未同步内容离开页面时触发浏览器提示。
- 主动退出时清理该账号的本地副本；清理失败明确提示并阻止继续在本机使用该账号存储。

状态机与迟响应：`synced / unsynced / saving / failed / conflict`。保存请求携带发送时的修订号；响应返回时若期间又有新输入，**不得标记为已同步**。没有新修改时不重复提交（重复提交会用同一提交标识携带新的基础版本，被服务端判为幂等冲突）。版本冲突立即暂停自动提交并保留当前文本，只提供复制/导出与“载入服务器版本”两个出口；“载入服务器版本”不删除冲突副本，刷新后仍可恢复。

## 6. 过程中发现并修复的缺陷

1. 幂等操作名使用驼峰（`article.saveDraft`）不满足既有操作名正则，**每次草稿保存都返回 400**；改为 `article.save_draft`。
2. 程序化替换正文（恢复副本、载入服务器版本）被当作输入，触发多余保存并提前复位“未同步”标记；编辑器区分用户输入与程序化同步。
3. 保存成功后排队中的重复提交用同一提交标识携带新基础版本，被判为幂等冲突并显示为版本冲突；调度器在无新修改时不再重复提交。
4. 本地副本的“未同步”标记从不复位，导致恢复对话框把已同步副本也列为待恢复；保存成功后按修订号复位本窗口副本。
5. 插入被跳过时仍提示“已插入图片”（假成功）；插入失败改为把受控链接提示给用户。
6. 窄视口下 `.pane-preview .editor-pane` 同时隐藏了预览面板自身；区分源码与预览分节类名。
7. 调度器就绪前的输入（会话握手与 CSRF 抓取期间）不会被纳入保存；挂载即创建调度器并合并就绪前的输入。
8. 开发态严格模式会挂载两次，输入可能落在两次挂载之间，被销毁的实例取消定时器后新实例没有待保存内容；新实例创建时若已发生过输入就继续安排保存，并沿用最后一次确认的服务器版本，避免用过期基础版本提交。

## 7. B2 审查修复

本次修复针对审查发现的六项缺陷，未扩展发布功能：

1. 创建和保存响应中的 `version` 始终来自本次幂等回执；`draft` 是当前可读草稿，可能已被其他窗口推进。编辑器遇到二者版本不同就进入冲突状态，保留当前输入，不采用未知新版本作为后续保存基础。同键重放不重复写入。
2. 编辑器窗口持有持续监听的 BroadcastChannel 租约，关闭或卸载时释放。既有窗口持续回答复制标签页的占用探测；同时争用相同标识时按请求标识选出唯一持有者。没有协调通道时分配新标识，仍可按账号和草稿发现旧副本。
3. 本地备份从首次待备份输入起最多等待 1 秒，连续输入不再延迟定时器。备份独立于服务器保存，发生版本冲突后继续运行。
4. 用户载入服务器版本前先确认当前文本的本地备份成功；读取期间如又有输入，则保留文字并要求重试。载入后修订号保持单调递增，并更新提交标识的作用域，避免旧幂等键用于新内容。
5. 本地写入串行化，服务器确认后按最新修订状态写入同步标记；IndexedDB 写入须等到事务完成才报告成功，临时副本迁移在同一事务执行。存储错误不反转已经成功的服务器保存。
6. 首次创建草稿和后续保存共用媒体引用校验/登记，在同一数据库事务中检查归属、就绪状态并更新 `draft_media`，避免已确认保存的图片被孤儿清理删除。引用校验失败时文章、草稿和幂等记录均回滚。

新增回归包含：连续输入、冲突后备份、载入后修订号、晚到响应与销毁、实际 BroadcastChannel 的延后复制与同时争用；接口验证回执版本、首次媒体引用与失败回滚；真实文件验证超过清理宽限期后仍能读取；桌面/手机验证丢失响应后的跨窗口重放、载入后继续保存及复制标签页副本隔离。
