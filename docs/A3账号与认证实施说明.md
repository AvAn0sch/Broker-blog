# A3 账号与认证实施说明

日期：2026-10-15。范围：真实注册/登录、图形验证码、数据库会话、CSRF、持久限流、账号权限、受限管理员初始化与测试密码重置，以及桌面/手机表单。A4 导航骨架、资料编辑和后续业务权限仍按开发规划推进。

## 1. 已实现的流程

- `/register`：昵称、邮箱、密码、图形验证码全部经服务端校验；只创建普通用户，成功后登录。
- `/login`：只校验已有账号；邮箱不存在或密码错误返回相同提示，不自动建号。
- `/account`：显示当前账号资料、身份和状态；游客跳转登录。账号被封禁后保留只读查看和退出。
- `/admin`：要求当前会话对应的账号仍为正常管理员；普通用户或封禁管理员不能访问。
- 退出撤销数据库中的原会话。登录和注册成功时更换浏览器绑定与会话，已有会话被替换。
- 返回地址仅接受本站路径；无效地址回到 `/account`。登录成功不代替用户自动执行原业务操作。

邮箱只作登录标识，统一去除两端空白并转为小写，不代表已验证邮箱归属。本期没有邮件服务或公开找回密码接口。

## 2. 固定参数

参数集中在 `src/modules/identity/policy.ts`，开发、测试和生产使用相同成本与阈值。

| 项目 | 当前值 |
| --- | --- |
| 密码 | 12–128 个 JavaScript 字符单位；不裁剪空格、不自动转换密码 |
| 密码哈希 | Node.js 原生异步 scrypt；N=131072、r=8、p=1；随机 16 字节盐；64 字节派生值；maxmem=192 MiB |
| 哈希并发 | 每个 Web 进程最多 2 次；超出返回可重试的 503，不无限排队保存密码 |
| 会话 | 32 字节随机 token；固定有效期 7 天；库中仅保存 HMAC 校验材料 |
| 匿名浏览器绑定 | 32 字节随机 token；Cookie 有效期 24 小时 |
| 验证码 | 6 位随机字母/数字；10 分钟；最多 5 次尝试；大小写不敏感 |
| 验证码获取/刷新 | 每浏览器每 10 分钟 20 次 |
| 注册 | 每浏览器、每规范化邮箱每小时各 5 次 |
| 登录 | 每浏览器、每规范化邮箱每 15 分钟各 10 次 |
| 总量保护 | 验证码、注册、登录三个动作分别每分钟 100 次 |
| 请求体 | JSON，最多 8 KiB；严格字段校验，注册不接受 role/status |

scrypt 成本采用 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)列出的配置之一；实现使用 [Node.js 22 crypto.scrypt](https://nodejs.org/docs/latest-v22.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)。当前阈值面向本地 MVP；公开部署前需要根据容量和可信反向代理配置评估请求来源限流，当前不信任客户端自行声明的转发 IP。

## 3. 验证码与失败处理

验证码由服务端随机生成并绘制为 PNG 像素，普通接口只返回挑战 ID、图片和到期时间。没有 SVG 文本、答案字段或带答案的替代文本。数据库使用带服务端密钥的 HMAC 保存答案校验材料，并绑定匿名浏览器与 register/login 用途。

刷新在事务中使同浏览器、同用途的旧挑战失效。事务级锁与 `0002_a3_identity.sql` 的唯一索引保证同一绑定最多一个未消费、未失效的挑战。验证时锁定挑战行，校验成功后先提交消费，再执行密码校验或注册；即使后续密码错误，也不能复用已消费的挑战。

错误计数、成功消费、限流计数各自在相应事务中提交，不能被后续业务失败回滚。跨浏览器、跨用途请求不会消耗合法浏览器的尝试次数。第 5 次错误后，即使随后提交正确答案也必须刷新。

页面展示加载、提交中、字段错误、验证码失效和网络失败状态；失败后刷新挑战，用户可手动重试。自动化测试验证真实图片解码、刷新、错误、过期、消费、跨会话、跨用途及并发唯一消费；不将这些结果视为抗 OCR 效果评估。

## 4. 会话、CSRF 与权限

Cookie 统一为 HttpOnly、SameSite=Lax、Path=/。HTTPS 下使用 Secure 和 `__Host-` 名称，不设置 Domain；`APP_ENV=production` 必须配置 HTTPS 的纯站点 Origin。`localhost` 与 `127.0.0.1` 是不同 Origin，本地请使用 `.env.local` 配置对应的入口。

`GET /api/v1/auth/context` 建立匿名浏览器绑定，返回该浏览器的预登录 CSRF token；已登录时另外返回会话 CSRF token。Cookie 中的随机会话凭证不进入 JSON 响应。验证码、注册、登录须同时满足精确 Origin 和匿名 CSRF 校验；退出要求当前会话 CSRF。认证 API 响应使用 no-store，且不开放跨域读取。

业务模块可使用 `authenticatedTransaction`：写操作先验证 Origin，再在事务中锁用户、会话，核对有效期、撤销状态、CSRF、实时角色与封禁状态。账号 ID 来自会话，不接受浏览器指定 actorId。状态读取不缓存登录时的角色；用户封禁/降权后，原会话也立即受当前权限约束。

SameSite 作为附加保护，不代替服务端 Origin 与 CSRF 校验。设计依据见 [OWASP CSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。实际文章、互动和治理写接口将在对应阶段接入此事务入口；本步不宣称全部业务权限矩阵已验收。

## 5. 受限本地管理脚本

脚本仅允许 development/test 环境、`.test` 合成邮箱和工作目录 `.local` 内不超过 4 KiB 的输入文件。密码不通过命令参数、终端输出或 Git 保存。先在忽略目录中创建私有 JSON 文件，完成后自行删除输入文件。

初始化文件字段：`email`、`password`、`nickname`。密码须满足上述规则。

```powershell
pnpm accounts:init-admin --input-file .local/admin-input.json
```

仅在没有管理员且目标邮箱未被占用时创建管理员；重复运行返回冲突，不覆盖密码，不提升已有普通用户。成功初始化写入审计。

重置文件字段：`operatorEmail`、`email`、`password`、`reason`。operatorEmail 须是库中正常管理员，email 为目标测试账号。

```powershell
pnpm accounts:reset-password --input-file .local/reset-input.json
```

本地操作系统访问权是这两个脚本的授权边界。密码哈希更新、撤销该账号全部会话及审计记录在同一事务提交；与登录共用用户行锁，阻止重置期间签发基于旧密码的会话。没有对应的公开 HTTP 管理接口。

普通用户可直接通过注册页面创建；建议本地测试使用 `.test` 邮箱，以便需要时用受限脚本重置。

## 6. 测试与环境

```powershell
pnpm check
pnpm test:auth
pnpm verify:auth
pnpm build
pnpm compose:test
```

`test:auth` 执行认证接口/服务与桌面/手机流程；`verify:auth` 包括当前全部规则、接口、数据库和浏览器回归。每轮使用独立 schema、媒体目录和随机 run ID；运行结束清理数据库、测试验证码答案及媒体，保留报告。

Linux test 容器现在启动自己的生产构建应用，绑定本轮测试 schema 和媒体目录；不再借用常驻 Web 容器执行业务写入。worker 持久化用例启动的实际进程也绑定本轮 schema，常驻 worker 无权消费该命名空间中的任务。外部 `PLAYWRIGHT_BASE_URL` 被拒绝，避免误测其他环境。

内部验证码适配器仅在 `APP_ENV=test`、`TEST_CONTROLS=true`、运行 ID、schema、目录和 manifest 一致时写入/读取答案。文件位于本轮媒体目录中的受限内部子目录；没有 HTTP 答案接口或万能答案。非测试环境开启控制开关会失败。自动化仍填写真实表单并走完整校验。

认证用例关闭网络轨迹和自动截图，禁止自动页面文本快照；静态布局截图在输入凭证前生成并遮罩验证码图片。测试账号使用随机运行凭证，报告只记录状态和错误码。报告的 `configurationVersion=a3-v1`、`datasetVersion=identity-v1`，其余 commit/dirty/清理信息沿用 A2 机制。

Windows 的 Turbopack 开发模式在完整并发测试中出现持续重编译和页面重载，因此 `pnpm dev` 与原生浏览器测试显式使用当前 Next.js 支持的 `--webpack`。生产构建仍使用 Turbopack，Linux 验证运行生产服务器。验证码适配器通过 Node 运行时读取内部文件，避免将答案文件作为静态构建输入。

Web/worker 启动脚本在启动进程前校验环境。容器保留供 Web、worker 和迁移共同使用的完整依赖，使用标准 Next.js 构建与 `next start`，移除了未使用的 standalone 输出配置。
