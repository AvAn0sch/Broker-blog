## 本地配置与目录

| 位置 | 作用 |
| --- | --- |
| `.env.local` | 本地应用、数据库连接、随机密钥 |
| `.env.test.local` | 测试库和端口 3100，独立随机凭证 |
| `.env.compose.local` | Linux 容器专用随机凭证 |
| `.tools/postgresql/pgsql/bin` | 项目内原生数据库程序 |
| `.local/postgres/data` | 数据库集群，包含开发库与测试库 |
| `.local/postgres/admin-password` | 仅本地启停/初始化脚本使用的引导凭证 |
| `.local/media/{development,test}` | 非公开静态目录的真实图片存储 |
| `.local/playwright` | 当前 Playwright 对应的浏览器 |
| `.local/worker-heartbeat.json` | 当前 worker 的数据库连通性心跳 |

配置生成和数据库启动可重复执行，不覆盖已有密钥，不删除已有数据；关闭集群通过 `pg_ctl` 安全停止。本次没有注册 Windows 服务或修改系统全局 Node.js/包管理器版本。实际运行命令见仓库 README。

## A2 补充

A2 已落地数据库结构、迁移与任务执行能力，更新后的命令和报告目录见 [A2 基础设施实施说明](A2基础设施实施说明.md)。本节之前的记录为 A1 历史结果。

2026-10-15 再次启动 Docker Desktop 时，出现 `removing stale socket ... userAnalyticsOtlpHttp.sock: The file cannot be accessed by the system`。本机确认 Docker 已退出，且 `%LOCALAPPDATA%\Docker\run` 仅含这一零字节 ReparsePoint 文件；单独重命名文件被 Windows 拒绝后，将整个 run 目录保留为 `run.stale-20261015-a2`，Docker 重建运行目录并恢复 Linux 引擎。镜像、数据库卷、WSL 发行版和配置保留，未恢复出厂设置。

遇到类似错误应先核对实际目录内容与进程状态；这里记录的是本机确认后的处理结果，不把其他 Docker 数据目录纳入清理。相关同类报告见 [Docker 启动问题记录](https://github.com/docker/for-win/issues/14176)。
